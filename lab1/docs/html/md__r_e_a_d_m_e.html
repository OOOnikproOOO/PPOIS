Возможности классов

Set (Множество)

  • Элементом может быть другое множество.
  • Проверка на пустоту и определение мощности множества.
  • Добавление и удаление элементов.
  • Проверка принадлежности элемента ([]).
  • Сравнение множеств на равенство (==, !=).
  • Объединение (+, +=), пересечение (*, *=) и разность (-, -=).
  • Построение булеана (множества всех подмножеств).
  • Формирование множества из строки и потоковый ввод/вывод (<<, >>).

TicTacToe (Крестики-нолики)

  • Игровое поле произвольного размера (от 3x3 и больше).
  • Проверка возможности установки крестика/нолика в указанной позиции.
  • Чтение и установка значения клетки через перегрузку ([]).
  • Автоматическая смена активного игрока.
  • Проверка победы одного из игроков по строкам, столбцам и диагоналям.
  • Проверка на ничью.
  • Сравнение состояний игр (==, !=).
  • Потоковый ввод/вывод игрового поля (<<, >>).

Сборка из консоли (без IDE)

Проект собирается с использованием CMake. Нужно убедиться, что установлены CMake (≥ 3.14) и компилятор с поддержкой C++17. Библиотека тестирования GoogleTest подтягивается автоматически.

Linux / macOS

cmake -S . -B build
cmake --build build

Windows

cmake -S . -B build
cmake --build build

Запуск

После успешной сборки в папке build (или build/Debug на Windows) появятся исполняемые файлы. Интерфейс полностью отделен от логики предметной области.

Запуск консольного меню (CLI):

  • Windows: .\build\Debug\Lab1_Run.exe
  • Linux: ./build/Lab1_Run

Тестирование

Проект покрыт unit-тестами с использованием GoogleTest (покрытие > 90%). Поскольку тесты интегрированы в CMake (CTest), запустить их можно двумя способами из консоли:

Способ 1: Прямой запуск

  • Windows: .\build\Debug\Tests_Run.exe
  • Linux: ./build/Tests_Run

Способ 2: Через CTest

cd build
ctest --output-on-failure

Документация

Для генерации документации нужно перейти в корень проекта и выполнить:

doxygen Doxyfile

Затем откройте файл docs/html/index.html в браузере.

CI/CD Pipeline

При каждом пуше или Pull Request автоматически запускается GitHub Actions workflow (.github/workflows/ci.yml), который выполняет:

  1. Сборку проекта (CMake).
  2. Запуск всех unit-тестов.
  3. Проверку кода линтером (cpplint).
  4. Публикацию исполняемого артефакта в Releases (при пуше тега версии).
